ai-chat-agent · Agent 循环是怎么工作的

模型不会调工具

你想知道「北京天气」，可模型没法上网。它不是自己去查天气，而是输出一张 调用单——要调哪个函数、传什么参数。真正执行函数、把结果喂回去的，是你的程序。

所谓 Agent，不是「AI 会自己动手」，而是： 模型输出 tool_calls（调用意图），你的程序执行工具、把结果回喂，再让模型据此作答。

这个「调 → 执行 → 回喂 → 再调」的循环，就是 Agent 的全部。 下面所有图，画的都是同一个循环。

第一步

一轮对话 = 一个循环

以前（阶段一）一轮对话只调一次模型。现在模型可能先回一句 「我要调 weather」，你的程序就得多跑几趟——每跑一趟，要么执行工具、要么得到答案。 循环的出口只有一个：模型不再要工具了。

Agent 只产出事实，界面的事归投影层。 runAgentTurn 返回的 final / added / stopReason 里没有任何一个字段是为界面存在的； 「调了哪个工具、传了什么、成没成功」全部由 presentation/transcript.ts 从 added 推导出来。

第三步

循环里的三个兜底

工具执行出错了怎么办？

不崩溃。把错误文本当作那条 tool 消息的 content 回喂给模型， 让模型看到「工具报错了」后自行换个参数或改口。 arguments 是非法 JSON 时同理。

模型一直要调工具呢？

maxSteps（默认 6）给循环设了上限。跑满仍没收敛，就追加一条 「已达最大步数」并停止。这就是「Agent 为什么会无限循环」的答案——必须有界。

请求失败会污染历史吗？

不会。工具消息和最终回答只在 runAgentTurn 成功返回后 才一次性写进 Session。中途失败，本轮只留下 user 那一条。

关联知识

两个接缝，都能换成假的

阶段一只有 LLMClient 一个接缝。阶段二多了 ToolRegistry， 另外多了一个「端口」接缝：createApp(deps) 只造 app 不 listen，测试才能用临时端口跑它。 三者都由 main.ts 装配，于是整个 Agent 循环都能在没有网络、没有 API key 的情况下断言—— 测试里塞一个「先说 tool_calls、再给答案」的假 client 和一个「返回 25°C, Sunny」的假 registry 即可。

LLMClient · 模型接缝

chat(messages, { tools }) → ChatResult。 测试替身：一个返回固定 tool_calls 或 content 的函数。

ToolRegistry · 工具接缝

list() / execute(name, args)。接口在 core/、实现在 tools/； 将来接 MCP 只给实现加 mount()，接口与 core 都不用动。
